# Лабораторная работа 4: Scrapy + Playwright

Система сбора данных с двумя пауками: статический новостной сайт и динамический магазин
на JavaScript. Данные проходят через конвейер очистки, дедупликации и валидации,
выгружаются одновременно в JSON и CSV.

```
lab4/
├── run_spider.py            CLI: --spider, --keywords, --output
├── scrapy.cfg
├── requirements.txt
├── Dockerfile               опциональный пункт задания
├── test_webmining.py        39 тестов, сеть не нужна
├── practice4.ipynb          тетрадь с прогоном обоих пауков
├── webmining/
│   ├── settings.py          задержки, retry, pipelines, Playwright
│   ├── items.py             NewsItem, ProductItem

│   ├── sites.py             профили сайтов: адреса и селекторы
│   └── spiders/
│       ├── news.py          NewsSpider — статика (SSR)
│       └── ecommerce.py     EcommerceSpider — динамика (SPA + Playwright)
├── output/                  создаётся при запуске: .json и .csv
└── logs/                    создаётся при запуске: лог каждого паука
```

# Установка

```powershell
cd C:\projects\web-mining\lab4
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
playwright install chromium
```

`playwright install chromium` обязателен: пакет `playwright` из pip — это обёртка,
сам браузер качается отдельно (около 150 МБ). Без него EcommerceSpider упадёт
с `Executable doesn't exist`.

Если PowerShell отказывается запускать `Activate.ps1`:
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.

Тетрадь `practice4.ipynb` исполняется не в терминале, а в своём ядре, поэтому после
установки нужно выбрать его: `Select Kernel` в правом верхнем углу тетради → `.venv`
этой папки. `ipykernel` ставится из `requirements.txt`, отдельная установка не нужна.
Первая ячейка проверяет окружение и, если пакетов нет, печатает, чего не хватает.

# Запуск

```powershell
python run_spider.py --spider news --keywords "ИИ,нейросети" --output news.json
python run_spider.py --spider ecommerce --category laptops --output prices.json
```

| Аргумент | Значение |
|---|---|
| `--spider` | `news` или `ecommerce` (обязательный) |
| `--output` | имя файла результата (обязательный); рядом всегда пишутся и `.json`, и `.csv` |
| `--keywords` | слова через запятую: оставить только записи, где они встречаются (для `news`) |
| `--category` | категория товаров, например `laptops` или `tablets` (для `ecommerce`) |
| `--site` | откуда собирать: `habr`, `lenta` для новостей; `testshop`, `wildberries` для товаров |
| `--limit` | сколько записей собрать, по умолчанию 100 |

Расширение в `--output` роли не играет: задание требует оба формата, поэтому берётся
только основа имени и создаются оба файла. Лог пишется в `logs/<паук>.log`.

## Что получается

| Файл | Что это |
|---|---|
| `output/news.json`, `output/news.csv` | статьи: заголовок, адрес, дата, краткое описание |
| `output/prices.json`, `output/prices.csv` | товары: название, адрес, цена, валюта, рейтинг, отзывы |
| `logs/news.log`, `logs/ecommerce.log` | полный лог Scrapy и отчёт каждого pipeline |

# Пауки

## NewsSpider — статика

Новостные страницы отдаются сервером уже готовыми (SSR), браузер не нужен: обычный запрос
Scrapy, дальше CSS-селекторы. Пагинация — по номеру страницы в адресе, а не по ссылке
«Следующая»: номер страницы стабильнее вёрстки, которую сайт может поменять.

Сколько страниц понадобится, заранее неизвестно: фильтр по словам и дедупликация отсеивают
часть записей. Поэтому паук запрашивает следующую страницу до тех пор, пока не наберёт
`--limit` записей, **прошедших pipelines** — счётчик подключён к сигналу `item_scraped`.
Ограничение `MAX_PAGES = 30` не даёт уйти в бесконечный обход, если ключевые слова слишком
узкие; в этом случае в логе появляется предупреждение с фактическим числом записей.

Ключевые слова фильтруют записи по заголовку и описанию. Сколько отсеялось, видно в логе.

## EcommerceSpider — динамика

Магазин отдаёт пустой контейнер, карточки товаров дорисовывает JavaScript, поэтому запрос
помечается `meta={"playwright": True}` и уходит через браузер. Дальше:

1. `wait_for_selector` — ждём появления первой карточки в DOM;
2. двенадцать раз подряд: прокрутка вниз через `evaluate` и пауза — так подгружаются
   остальные товары (infinite scroll);
3. `response.css(...)` работает как обычно, но уже по отрендеренной странице.

Через браузер идут только запросы с этой пометкой — новости собираются обычным способом,
без лишних накладных расходов.

## Профили сайтов

Все адреса и селекторы вынесены в `webmining/sites.py`. Если сайт поменяет вёрстку,
править нужно одно место, а не код паука. Паук предупреждает в логе, когда на странице
не нашлось ни одной карточки, — сломанный селектор виден сразу, а не по пустому результату.

По умолчанию товары собираются с `webscraper.io/test-sites/e-commerce` — это каталог,
созданный специально для тренировки скрапинга: настоящий SPA с подгрузкой при прокрутке,
без капчи и без запрета в правилах.

Рядом лежит профиль `wildberries`. Он оставлен как заготовка, но честно скажу: настоящие
маркетплейсы закрыты антиботовой защитой и запрещают автоматический сбор в правилах
пользования. Паук, скорее всего, получит капчу и соберёт ноль записей — в логе это будет
видно по предупреждению «ни одной карточки».

# Pipelines

Порядок задан в `settings.py`, меньшее число — раньше.

| Pipeline | Что делает |
|---|---|
| `CleaningPipeline` (100) | `ftfy.fix_text` чинит кракозябры, `strip` и схлопывание пробелов, нижний регистр для описаний |
| `DuplicationPipeline` (200) | отбрасывает повторы: ключ — адрес без параметров запроса, а если адреса нет, то заголовок |
| `ValidationPipeline` (300) | отбрасывает записи без заголовка или адреса и с ценой вне разумных границ |

Каждый pipeline по окончании пишет в лог, сколько записей обработал или отбросил:

```
[webmining.pipelines] INFO: CleaningPipeline: поправлено полей — 138
[webmining.pipelines] INFO: DuplicationPipeline: отброшено дубликатов — 11
[webmining.pipelines] INFO: ValidationPipeline: отброшено записей — 1
```

Нижний регистр применяется только к описаниям и названию источника: у заголовков он съедает
имена собственные, а для поиска по тексту описания регистр не нужен. Поле, к которому его
применять, задаётся списком `LOWERCASE_FIELDS` в `pipelines.py`.

# Обработка ошибок

| Настройка | Зачем |
|---|---|
| `RETRY_ENABLED`, `RETRY_TIMES = 3` | три повтора при сбое |
| `RETRY_HTTP_CODES = [429, 500, 502, 503, 504]` | 429 «слишком много запросов» и 503 «сервис недоступен» — из требований задания |
| `DOWNLOAD_DELAY = 2`, `DOWNLOAD_DELAY_JITTER = 0.5` | пауза между запросами с разбросом ±50% |
| `CONCURRENT_REQUESTS_PER_DOMAIN = 2` | не больше двух одновременных запросов на сайт |
| `ROBOTSTXT_OBEY = True` | уважаем правила сайта |
| `USER_AGENT` | на стандартный User-Agent Scrapy многие сайты отвечают 403 |

Ошибки запросов ловит `errback` паука и пишет в лог с текстом причины. Пустая страница
и сломанный селектор — это предупреждение, а не молчаливый ноль записей.

# Отличия от кода на слайдах

Scrapy 2.13 изменил два интерфейса, которые в лекции показаны в старом виде. Проект
использует актуальные — иначе паук либо не запустится, либо засыплет лог предупреждениями:

| На слайде | В проекте | Почему |
|---|---|---|
| `def start_requests(self)` | `async def start(self)` | с 2.13 Scrapy вызывает `start()`; старый метод просто не вызывается, и паук собирает ноль записей |
| `process_item(self, item, spider)` | `process_item(self, item)` | аргумент `spider` объявлен устаревшим, логируем через логгер модуля |
| `RANDOMIZE_DOWNLOAD_DELAY = True` | `DOWNLOAD_DELAY_JITTER = 0.5` | настройка переименована |

`--limit` и подсчёт записей по сигналу `item_scraped`.

# Если что-то не работает

| Симптом | Причина и что делать |
|---|---|
| `Executable doesn't exist ... chrome-headless-shell` | не скачан браузер: `playwright install chromium` |
| Паук собрал ноль записей, в логе «ни одной карточки» | сайт поменял вёрстку или закрылся от роботов — проверьте селекторы в `sites.py` |
| `ModuleNotFoundError` в терминале | не включён venv: `.\.venv\Scripts\Activate.ps1`, в приглашении должно появиться `(.venv)` |
| `ModuleNotFoundError` в тетради | ядро тетради смотрит в другое окружение. Кнопка `Select Kernel` в правом верхнем углу → `.venv` этой лабораторной. Быстрая альтернатива — выполнить `%pip install -r requirements.txt` ячейкой в самой тетради |
| Много `429` в логе | сайт ограничивает частоту: поднимите `DOWNLOAD_DELAY` в `settings.py` |
| Записей меньше 100 | ключевые слова слишком узкие: паук дошёл до `MAX_PAGES` — в логе будет «Остановился на странице». Уберите часть слов или поднимите `MAX_PAGES` в `news.py` |
| Кириллица в CSV ломается в Excel | откройте через «Данные → Из текста» с кодировкой UTF-8 |
